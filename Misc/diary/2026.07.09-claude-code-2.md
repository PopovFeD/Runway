## Дата

09.07.2026, вторая половина дня — ночь

## Итог дня одной строкой

От «жёсткий COM-порт из settings.json и один тип пакета» до «вкладочный GUI
по макету, типизированный протокол с двумя сенсорными типами, SQLite с
сессиями/событиями и фильтруемыми логами». Все изменения передавались
patch-файлами (`git am -3`) — запись в GitHub из сессии не работала (403).

## Хронология и решения

1. **Типизация протокола.** `PacketParser.Parse` → `abstract record Packet`
   (`TelemetryPacket`/`EnvironmentPacket`/`ControlPacket`). Новый тип
   сообщения `Environment = 0x11` (давление uint32 Па + свет uint32 сотых
   люкса) сквозь весь стек, включая эмулятор (каждый 5-й кадр). Цена
   расширения протокола: record + две ветки + константа в Python.

2. **Загадка флаки-тестов разгадана.** «То 0, то 2 ошибки» у `dotnet test` —
   это интеграционные тесты при ЗАНЯТОЙ паре com0com (эмулятор или само
   приложение держат COM4/COM6). Теперь `TestEnvironmentIsReady` мягко
   скипает их с `[SKIP]` в консоли. Гонок в коде не было.
   Тогда же: NU1903 (уязвимый транзитивный SQLite) закрыт прямой ссылкой
   `SQLitePCLRaw.bundle_e_sqlite3` (в NuGet ушла версия 3.0.0).

3. **Каркас GUI по макету** (`Misc/gui_mockups/`): постоянные верхняя и
   нижняя панели, сайдбар-вкладки (`TabControl TabStripPlacement="Left"`),
   Дашборд + Подключение живые, остальное заглушками.

4. **Логи в БД** (шаги 1–2 из `storage-and-logs-decision.md`):
   `IAppStore`/`SqliteAppStore` — таблицы sessions/telemetry/events,
   миграция старой БД на лету. Сессия = «Подключить»→«Отключить»
   (переподключения её не дробят). Вкладка «Логи» с фильтрами
   (уровень / текущая сессия), чтение по кнопке. `SaveEventQuietly` —
   недоступная БД не роняет ни UI, ни конвейер. Писателей в БД стало два
   (консьюмер кадров + UI-поток) — соединение под lock, id сессии через
   Volatile.

5. **Доводка GUI:** единая кнопка Подключить/Отключить в верхней панели
   (по факту подключения, не по выбору в списках), подпись Runway из панели
   убрана (дублировала заголовок окна), плитки Дашборда показывают последние
   значения по типам пакетов, живой вывод — в терминальном стиле с меткой
   времени и автопрокруткой вниз (code-behind: скролл — поведение View).

## 10.07: логи целиком в БД, галочки-фильтры, экспорт

Шаги 3–4 решения по хранению: `StoreLoggerProvider` (мост M.E.L→events,
session_id из общего `SessionTracker`), `runway.log`/`LogFileWriter` удалены,
diagnostics-файл остался «логом последней надежды». Порядок Dispose в App:
БД закрывается последней. Вкладка «Логи»: ComboBox уровня заменён галочками
Info/Warning/Error (+ «только текущая сессия»); `ReadEvents` принимает набор
уровней (IN-список параметрами, пустой набор = пусто). Экспорт CSV (`;` —
для русского Excel) по тем же галочкам — «что видишь, то и экспортируешь»,
в `exports/` рядом с приложением; выбор папки диалогом — потом.

## 10.07 (2): разделение MainWindowViewModel по вкладкам

`ConnectionViewModel` (транспорты/точки/статус/toggle/сессии, слушает
ConnectionStateChanged) и `LogsViewModel` (галочки/чтение/CSV-экспорт)
выделены; в корневой VM остались конвейер кадров и Дашборд. Сигнатура
конструктора корня сохранена — тесты правились только префиксами
(vm.Connection.*, vm.Logs.*). Общий код записи событий — расширение
IAppStore.TrySaveEvent. Кнопки Подключить/Отключить из вкладки
«Подключение» удалены — осталась единственная кнопка в верхней панели.

## 10.07 (3): экспорт телеметрии CSV/XLSX

`ExportViewModel` + вкладка «Экспорт» по макету (формат, «все записи»/«эта
сессия», счётчик «Всего в БД»). `IAppStore`: `ReadTelemetry(sessionId?)` и
`CountTelemetry()`. Писатели в `Core/Export`: CSV (';', invariant) и XLSX —
минимальный OpenXML вручную через ZipArchive, БЕЗ сторонних пакетов (xlsx —
это zip с XML; числа пишутся числами, чтобы Excel сразу строил графики;
таймстамп — строкой ISO, без возни с датами Excel). «Эта сессия» без
активной сессии — вежливый отказ в статусе. Тесты: CSV all/session,
xlsx-zip со значениями. Проверить руками: открыть .xlsx настоящим Excel.
